# 图床转站助手桌面版 使用手册

本手册是 [README](../README.md) 的补充，收录桌面版的详细使用说明与文件命名格式规范。

---

## 一、使用说明

### 1.1 图床配置管理

1. 切换到「图床配置」页签，点击「添加配置」
2. 选择图床类型，按提示填写凭据（如 Token、SecretId/SecretKey、存储桶、地域等），各项配置的所需字段见 [README 支持的图床](../README.md#六支持的图床)
3. 点击「测试」可验证配置连通性（会上传一张测试图片）
4. 勾选「设为默认」后，转换页将默认使用该配置；默认配置全局唯一
5. 已保存的配置可随时编辑、删除或设为默认

敏感字段（Token、SecretKey 等）以 AES-256-GCM 加密后存入本地 SQLite，界面回显时其他字段明文、敏感字段以掩码处理。

### 1.2 批量转换

1. 切换到「批量转换」页签，上传或拖入一个或多个 `.md` 文件，也可在左侧粘贴单篇 Markdown 后点击「加入队列」
2. 点击「批量识别」，自动列出全部图片地址与所属图床类型
3. 在右侧选择目标图床配置
4. 若识别到 GitHub 图片，会弹出加速代理设置（默认 `https://gh-proxy.com/`，可关闭）
5. 点击「开始批量转换」，任务进入后台队列，任务内多文档并发转换（并发度 3）
6. 转换完成后可逐个预览差异（最多展示前 20 行变化）、下载单个文档或选目录批量导出

批量转换只处理 `http://`、`https://` 远程图片地址；本地路径会保留原样并计入「无法转换」，请改用「本地上传」。

### 1.3 本地上传

1. 切换到「本地上传」页签，添加一个或多个 Markdown 文档
2. 添加本地图片文件，或直接拖入包含图片的目录
3. 应用按路径与文件名智能匹配文档中的本地图片引用（支持 `./images/a.png`、`images/a.png`、`C:\Users\demo\Pictures\a.png` 与 `<img src="...">` 标签）
4. 确认「未匹配」数量为 0 后，选择目标图床配置
5. 点击「上传并替换」，任务进入后台队列执行
6. 完成后下载替换后的文档

文档中的 `http://`、`https://` 远程图片地址会保持不变；如需转换远程地址请使用「批量转换」。

### 1.4 下载图片

1. 切换到「下载图片」页签，上传或拖入一个或多个含网络图片的 `.md` 文档
2. 应用自动识别其中全部 `http://`、`https://` 图片地址，并标注所属图床类型
3. 在右侧「下载设置」中选择下载目录（系统目录对话框）或直接输入路径
4. 点击「下载全部图片」，逐张下载并保存；汇总展示成功/失败数量
5. 失败的图片会逐图展示具体原因（如 GitHub raw 直连超时，可改用 `gh-proxy.com/` 前缀的代理地址重试）

同名文件自动追加序号（如 `a (1).png`），不会覆盖已下载的文件。

### 1.5 云同步

1. 切换到「云同步」页签，点击「连接 GitHub」：优先走设备码授权（需提前配置 OAuth App 的 client_id，见 [GitHub OAuth App 与 Device Flow 配置指南](github-oauth-device-flow.md)），也可粘贴具备 gist 权限的 GitHub 个人访问令牌（PAT）；令牌保存于系统钥匙串（无钥匙串环境回退机器绑定加密文件）
2. 点击「设置密码」设定同步密码：用于加密云端数据，不保存在本机——换设备必须输入同一密码，遗忘后云端数据无法解密；首次设置后自动同步一次
3. 开启「自动同步」后配置变更 3 秒自动上传，也可随时点击「立即同步」；窗口切回时自动对齐云端（30 秒节流）
4. 同步按三方合并执行：本机与云端各自的新增、修改、删除自动合并且双向传播；当合并结果可能大量缩水时会弹出横幅拦截，由你选择「恢复远端版本」或「强制推送」
5. 换设备或应用重启后，在「同步密码」行直接输入密码解锁（已锁定时行内输入，无需弹窗），解锁后自动对齐云端一次；「修改密码」需先验证当前密码
6. 两台设备同步密码不同时会出现冲突横幅：可输入云端密码恢复远端配置（本机密码随之重置），或用本地覆盖云端；修改同步密码后未发生配置变更就断开重连，也会进入该横幅——输入旧密码可恢复云端并撤回修改，用本地覆盖则让新密码生效
7. 点击「历史版本」浏览 Gist 修订历史并解密预览，「恢复此版本」为整体覆盖（不是合并）：本机与云端都回到该内容并作为新版本推送，被覆盖内容可从历史再次恢复
8. 「断开」清除本机令牌与同步快照（云端 Gist 保留）；重新连接后若已解锁且自动同步开启，3 秒后自动同步一次

同步状态行以徽章展示当前状态（就绪/同步中/冲突/已拦截/待恢复）与云端版本号。

同步范围仅图床配置；转换记录、任务等本地数据不上云。

### 1.7 关于

「关于」页签展示应用信息：

- 版本行显示当前安装的 PicBed Switcher Desktop 版本号
- GitHub 行为项目地址入口，点击右侧「github.com/zyx3721/picsw-rust」可在系统浏览器打开仓库主页，欢迎 Star 与 Issue 反馈

标题行右侧为「检查更新」按钮：

- 启动应用后会自动静默检查一次新版本；也可随时手动点击「检查更新」
- 已是最新版时提示「当前已是最新版」；检测到新版本时按钮左侧显示绿色「检测到新版本： vX.Y.Z」提示，按钮变为「更新到 vX.Y.Z」
- 点击「更新到 vX.Y.Z」后自动下载更新包（SHA-256 完整性校验），下载完成自动退出并静默安装到原路径（安装版静默安装后自动重启；便携版自动解压替换原文件并重启）
- Windows 以外的平台暂不支持应用内自动更新，点击后会打开发布页引导手动下载

### 1.6 历史记录

- 保留最近 50 条转换记录，展示源/目标图床、状态、图片数量与时间
- 支持勾选批量删除（单次最多 50 条）
- 点击记录可查看每张图片的替换明细：原地址、目标地址、状态与错误摘要
- 工具行支持搜索与筛选：搜索框匹配全部列与替换明细中的源/目标地址；状态、源图床、目标图床下拉按当前记录动态聚合；时间范围筛选边界如下（以当前时刻 2026-09-29 12:00:00 为例）

| 选项 | 筛选区间 | 举例 |
| --- | --- | --- |
| 全部时间 | 不限 | 显示全部记录 |
| 今天 | 当日 00:00:00 至当前时刻 | 昨天 23:59:59 不显示，今天 00:00:01 起显示 |
| 近 7 天 | 当前时刻 − 7×24 小时至当前时刻 | 09-22 12:00:00 起（按整日滚动，非自然日） |
| 近 30 天 | 当前时刻 − 30×24 小时至当前时刻 | 08-30 12:00:00 起 |
| 自定义 | 起始日 00:00:00.000 至 结束日 23:59:59.999 | 选 09-01 至 09-28 时首尾两天全天完整包含 |

## 二、文件命名格式说明

除 EasyImage 外，图床配置中可填写「文件命名格式」，用于控制图片上传到目标图床后的对象路径和文件名。留空时使用默认格式：

```text
{y}/{m}/{d}/{origin}{ext}
```

例如在 2026-05-18 上传 `cover.png`，默认会生成类似：

```text
2026/05/18/cover.png
```

可用变量如下：

| 变量 | 说明 | 示例 |
| --- | --- | --- |
| `{y}` | 当前年份，四位数 | `2026` |
| `{m}` | 当前月份，两位数 | `05` |
| `{d}` | 当前日期，两位数 | `18` |
| `{timestamp}` | 当前 Unix 秒级时间戳 | `1779087600` |
| `{origin}` | 原始文件名，不包含扩展名 | `cover` |
| `{name}` | 与 `{origin}` 相同，原始文件名不含扩展名 | `cover` |
| `{filename}` | 原始完整文件名，包含扩展名 | `cover.png` |
| `{ext}` | 原始扩展名，包含点号 | `.png` |
| `{hash}` | 图片内容的 SHA-1 哈希值 | `9f2a...` |
| `{random}` | 8 位随机十六进制字符串 | `a1b2c3d4` |
| `{rand:N}` | 指定长度的随机十六进制字符串，`N` 为正整数 | `{rand:6}` -> `a1b2c3` |

常见格式示例：

```text
# 按日期目录保存，保留原文件名
{y}/{m}/{d}/{filename}

# 按日期目录保存，文件名增加随机串，降低重名概率
{y}/{m}/{d}/{origin}-{rand:6}{ext}

# 使用内容哈希命名，适合去重和缓存
images/{hash}{ext}

# 使用时间戳和原文件名组合
uploads/{timestamp}-{origin}{ext}
```

命名格式中的路径分隔符 `/` 会作为图床对象路径使用；非法字符、空格和危险路径片段会被自动清理或替换为 `-`，避免生成不安全的对象名。

## 三、数据存储与备份

| 项 | 位置 |
| --- | --- |
| 程序文件 | 安装时选择的目录（Windows 默认 `%LOCALAPPDATA%\PicBed Switcher\`） |
| 业务数据 | 应用数据目录下的 `picbed.db`（Windows 为 `%APPDATA%\com.picsw.desktop\`） |
| 任务临时文件 | 应用数据目录下的 `local-tasks\<任务ID>\`（任务完成后自动清理） |

- 安装路径与应用数据目录相互独立，自定义安装位置不影响数据存放
- 备份：关闭应用后拷贝 `picbed.db`（建议连同 `-wal`、`-shm` 文件）
- 迁移：将备份文件放回新机器的应用数据目录即可
- 云同步相关数据不随 `picbed.db` 备份：GitHub 令牌存于系统钥匙串（或机器绑定加密文件），同步进度快照存于 WebView 本地存储；换机迁移后需重新连接 GitHub 并输入同步密码解锁，云端 Gist 会自动重新对齐
