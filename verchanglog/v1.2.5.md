## 📋 版本概述

v1.2.5 是针对图床上传稳定性的集中修正版本：解决 Gitee 并发建文件偶发失败、Gitee / GitHub 同名文件重试失败的问题，新增远程转换任务级上传缓存，并修复 EasyImage 失败原因被误报为「缺少图片地址」的问题；同时补齐 Gitee / GitHub / EasyImage 相关错误的英文映射。

无。本次为稳定性修复版本，不新增功能入口。

## 🐛 Bug 修复

- 修复 Gitee 并发建文件偶发失败：批量转换同时处理多个文档时，同一仓库分支的并发提交会返回 `{"message":"文件新建失败"}`；现在按 `repository + branch` 串行化建文件请求，并对该错误与系统繁忙、网络超时等瞬时错误自动重试 2 次，重名错误不重试。
- 修复 Gitee 同名文件重试失败：目标路径已存在时按 Git blob SHA1 判断内容，内容一致直接复用已有地址，不产生新提交；内容不同则明确提示调整文件命名格式或存储路径，不再笼统报「文件名已存在」。
- 修复 GitHub 同名文件重试失败：不带 `sha` 的 PUT 遇到已存在文件会返回 422 `sha wasn't supplied`；现在收到重名 422 后回查目标文件并比对 Git blob SHA1，内容一致复用已有地址，内容不同明确提示。
- 为 GitHub 增加同仓库分支写锁，并仅对 409 冲突、5xx 与网络错误重试，不重试重名、空仓库与限流，避免无意义重试。
- 修复 EasyImage 上传失败原因被误报：服务端返回 `{"result":"failed","code":202,"message":"Token Error"}` 等失败 JSON 时，旧逻辑统一报「缺少图片地址」；现在解析 `result` / `message` / `code` 并透出真实原因，例如 `EasyImage 上传失败：Token Error（code 202）`。
- 修复 EasyImage 相对图片地址无法识别：兼容 `/i/2026/a.png` 根相对地址与 `//cdn.example.com/a.png` 协议相对地址，按 API 地址补全为完整 URL。
- 改进 EasyImage API 地址诊断：地址返回 404 时提示检查是否为 `/api/index.php`；返回 HTML 或非 JSON 内容时提示检查 API 地址；地址缺少协议或主机时提示填写完整地址。
- 补齐 Gitee / GitHub / EasyImage 新增错误提示的英文映射，避免英文界面继续显示中文错误。

---

## 🚀 性能优化

- 远程转换新增任务级上传缓存：按「目标配置 ID + 源 URL」缓存上传结果，同一任务内多个文档引用相同图片时只下载上传一次。
- 使用 `tokio::sync::OnceCell` 合并并发请求，避免多个文档同时转换时重复上传同一张图片。

---

## 🔄 重构优化

- 新增 `uploader/repo.rs`，抽取仓库图床共用的按仓库分支写锁与 Git blob SHA1 计算，Gitee / GitHub 统一复用。
- Gitee 上传器改为「预检目标路径 → 比对 SHA → 建文件」，GitHub 上传器采用「先 PUT → 重名 422 后回查」的轻量幂等方案。
- EasyImage 上传器改为自行解析状态码、响应体与 URL，不再依赖通用 JSON 响应封装，错误信息更准确。
- 新增 `src/i18n/errorText.ts` 后端中文错误映射层，转换面板、历史详情、下载面板与 IPC 错误统一走映射。

## 🔄 升级说明

v1.2.4 → v1.2.5 无数据迁移要求，安装包覆盖安装即可，本机配置、任务历史、云同步数据与密码均保留。

行为变化说明：

- Gitee / GitHub 同名同内容重试会自动复用已有地址；同名不同内容会明确报错，请调整文件命名格式或存储路径后再转换。
- 对象存储（腾讯云 COS / 阿里云 OSS / 七牛 / 百度 BOS / 华为 OBS / MinIO）与又拍云仍保持同名覆盖语义，不受本次改动影响。
- EasyImage 测试若提示 API 地址不存在，请确认地址为 `/api/index.php`；若提示 `Token Error`，请检查 Token 是否与服务端一致、是否过期或带多余空格。
